# 上架说明

把扩展发布到 pcl-next 扩展市场，需要你有一个公开 GitHub 仓库。整个过程不需要联系维护者，也不需要提交 PR —— 打上 topic、发 Release，下一小时的索引扫描就会收进去。

## 一、准备仓库

1. 仓库**必须公开**（私有仓库的 raw 与 Release 都取不到）。
2. 仓库根目录放 `plugin.json`，内容与打进 `.pclnx` 包里的那份完全一致：

```json
{
  "schema": 1,
  "id": "your-name.mirror-pack",
  "name": "示例镜像源",
  "version": "1.2.0",
  "level": "L0",
  "description": "给下载列表补充一个镜像源。",
  "extensions": ["download.source"],
  "mirror": { "base": "https://mirror.example.com/mc/", "weight": 5, "name": "Example" }
}
```

字段规则见 pcl-next 仓库的 `docs/扩展规范.md`。摘要：

| 字段 | 要求 |
|---|---|
| `id` | 小写 ASCII，`a-z0-9` 与 `. _ -`，2–64 位，**全局唯一**，建议带作者前缀 |
| `version` | `1.0.0` 这类数字点分格式 |
| `level` | `L0`（只声明数据）或 `L1`（含代码级补丁） |
| `description` | 必填，一句话说明用途 |
| `extensions` | 至少一项，只能取已定义的扩展点 |
| `entry` / `mixin` | `L0` 不允许有；`L1` 必须有 `entry`（包内 `.dll`）且声明 `mixin.patch` |

3. 仓库打 topic：仓库页右上角 **About → Topics** 添加 `pclnext-plugin`。

## 二、打包与发版

1. 把扩展打成 zip，改后缀为 `.pclnx`（容器就是 zip，不依赖后缀）：
   包内结构 = `plugin.json` + 你声明的资源/程序集，`plugin.json` 在**包根**。
2. 建一个 Release，tag 必须与清单的 `version` 一致（`v1.2.0` 或 `1.2.0` 都行）。
3. Release 附件必须**恰好一个**以 `.pclnx` 结尾的文件，例如 `your-name-mirror-pack-1.2.0.pclnx`。
4. 附件不要换名后再上传第二份，也不要附带第二个 `.pclnx`（脚本取第一个 `.pclnx` 资产，容易取错）。

> sha256 不用你手填：GitHub 会给每个 Release asset 生成 `digest`（`sha256:...`），脚本直接读取；若某天 digest 缺失，脚本会下载附件现场计算。

## 三、等索引刷新

- Actions 每小时第 17 分跑一次，也可以由维护者手动 `workflow_dispatch` 触发；
- 收录成功：`market/index.json` 出现你的条目，客户端 30 分钟内可见；
- 收录失败：打开 [Actions 日志](https://github.com/skchuowei/pcl-next-market/actions/workflows/build-index.yml)，搜你的仓库名，后面就是具体原因。

## 四、常见被跳过的原因

| 日志原因 | 怎么修 |
|---|---|
| `根目录没有 plugin.json` | 把清单放到仓库根，不是 `src/` 或 `docs/` 里 |
| `extensions 为空` | 至少声明一个扩展点；没有扩展点的包装上也无效 |
| `level=L1 必须声明 entry 且指向 .dll` | L1 的入口程序集路径写错了，或漏了 `mixin.patch` |
| `版本不一致` | Release tag 与 `plugin.json` 的 `version` 对齐（`v` 前缀可有可无） |
| `Release 里没有 .pclnx 附件` | 附件后缀必须是 `.pclnx`（`.zip` 不算） |
| `无法获取附件 sha256` | asset 的 digest 缺失且下载失败，重新上传附件即可 |

## 五、更新与下架

- **更新**：改 `plugin.json` 的 `version` → 发新 tag 与新 Release → 下一小时自动替换索引里的旧版本；
- **下架**：删除 Release 或删掉 topic。索引会保留「最近一次成功收录」，所以主动下架需要联系维护者编辑 `market/index.json`，或直接把仓库转为私有/删除。

## 六、不需要做的事

- 不用提交 PR、不用填表；
- 不用在仓库里放 `index.json`、`sha256` 文件；
- 不用把 `.pclnx` 提交进仓库（只走 Release 附件，避免仓库体积膨胀）。
